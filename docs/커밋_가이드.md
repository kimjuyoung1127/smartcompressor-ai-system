## 🚀 커밋 절차

### 1. 변경사항 확인

```bash
# 변경된 파일 확인
git status

# 변경 내용 확인
git diff
```

### 2. 스테이징

```bash
# 모든 변경사항 추가 (권장하지 않음)
git add .

# 특정 파일만 추가 (권장)
git add services/
git add routes/
git add docs/
git add Dockerfile
git add docker-compose.yml
git add env.example
```

### 3. 커밋

```bash
# 의미 있는 커밋 메시지 작성
git commit -m "feat: 실시간 모니터링 대시보드 성능 지표 시각화 추가

- 성능 메트릭 카드 4개 추가 (처리 시간, 처리량, 품질 통과율, 라벨링 완료율)
- 성능 차트 2개 추가 (처리 시간 추이, 처리량 추이)
- API 엔드포인트 추가 (/api/realtime/performance-metrics)
- 문서 추가 (실시간_대시보드_성능_지표_가이드.md)"
```

### 4. 푸시

```bash
# 현재 브랜치에 푸시
git push origin $(git branch --show-current)

# 또는 특정 브랜치에 푸시
git push origin feature/dashboard-improvement
```

## 📝 커밋 메시지 규칙

### 형식

```
<type>: <subject>

<body>

<footer>
```

### Type 종류

- `feat`: 새 기능 추가
- `fix`: 버그 수정
- `docs`: 문서 수정
- `style`: 코드 포맷팅 (기능 변경 없음)
- `refactor`: 코드 리팩토링
- `test`: 테스트 추가/수정
- `chore`: 빌드 설정, 패키지 관리 등

### 예시

```bash
# 기능 추가
git commit -m "feat: ESP32 통합 이상 감지 시스템 추가"

# 버그 수정
git commit -m "fix: 데이터 품질 검증 로직 오류 수정"

# 문서 추가
git commit -m "docs: 개발 워크플로우 가이드 추가"

# 여러 변경사항
git commit -m "feat: 실시간 대시보드 성능 지표 시각화 추가

- 성능 메트릭 카드 4개 추가
- 성능 차트 2개 추가
- API 엔드포인트 추가
- 문서 추가"
```

## 🔍 커밋 전 확인사항

### 1. .env 파일 확인

```bash
# .env 파일이 스테이징 영역에 있는지 확인
git status | grep .env

# 있다면 제거
git reset HEAD .env
```

### 2. 민감한 정보 확인

```bash
# 커밋할 파일에서 민감한 정보 검색
git diff --cached | grep -i "password\|secret\|token\|key"
```

### 3. 불필요한 파일 확인

```bash
# 커밋할 파일 목록 확인
git status --short

# 특정 파일 제외
git reset HEAD <파일명>
```

## ⚠️ 주의사항

1. **절대 커밋하지 말 것**
   - `.env` 파일
   - 데이터베이스 파일 (`*.db`)
   - 로그 파일 (`*.log`)
   - 민감한 정보 (비밀번호, 토큰, 키)

2. **커밋 전 확인**
   - `git status`로 변경사항 확인
   - `git diff`로 변경 내용 확인
   - 민감한 정보 검색

3. **의미 있는 커밋 메시지**
   - 무엇을 변경했는지 명확히
   - 왜 변경했는지 설명 (필요시)
   - 관련 이슈 번호 포함 (필요시)
