## 💰 개선사항별 비용 분석

### 1. 성능 최적화 및 병렬 처리

#### 리소스 사용량 변화:

**CPU 사용률:**
- 개선 전: 5-10% (순차 처리, 유휴 시간 많음)
- 개선 후: 15-25% (병렬 처리, 효율적 사용)
- **증가**: +10-15% (하지만 처리 시간 75% 단축)

**메모리 사용량:**
- 개선 전: 200MB
- 개선 후: 250-300MB (캐싱 추가)
- **증가**: +50-100MB

**네트워크:**
- 변화 없음 (동일한 데이터 전송)

#### 비용 영향:

**긍정적 효과:**
- ✅ 처리 시간 75% 단축 → 동일 시간에 더 많은 센서 처리 가능
- ✅ CPU 효율 향상 → 더 작은 인스턴스로도 처리 가능
- ✅ 응답 시간 단축 → 사용자 경험 개선

**부정적 효과:**
- ⚠️ CPU 사용률 증가 (하지만 효율적 사용)
- ⚠️ 메모리 50-100MB 증가

**비용 변화:**
- **추가 비용**: 거의 없음 (기존 인스턴스로 충분)
- **절감 효과**: 처리 시간 단축으로 동일 리소스로 더 많은 센서 처리 가능
- **순 비용**: **$0/월 (비용 변화 없음 또는 약간 절감)**

### 2. 실시간 대시보드 및 시각화 강화

#### 리소스 사용량 변화:

**WebSocket 연결:**
- 연결당 메모리: 약 1-2KB
- 동시 연결 10개: 약 20KB
- 동시 연결 100개: 약 200KB
- **메모리 증가**: 미미함

**실시간 데이터 전송:**
- 데이터 크기: 약 1-2KB/초 (JSON)
- 10개 연결: 약 10-20KB/초
- 100개 연결: 약 100-200KB/초
- **네트워크 대역폭**: 증가하지만 미미함

**서버 측 렌더링:**
- 차트 데이터 생성: CPU 1-2% 추가
- 클라이언트 측 렌더링: 서버 부담 없음

#### 비용 영향:

**긍정적 효과:**
- ✅ 클라이언트 측 렌더링 (서버 부담 최소)
- ✅ 효율적인 WebSocket (HTTP 폴링 대비 효율적)

**부정적 효과:**
- ⚠️ 메모리 약 20-200KB 증가 (미미함)
- ⚠️ 네트워크 대역폭 약간 증가

**비용 변화:**
- **추가 비용**: 거의 없음 (기존 인스턴스로 충분)
- **EC2 네트워크**: 무료 tier 내 (1TB/월 무료)
