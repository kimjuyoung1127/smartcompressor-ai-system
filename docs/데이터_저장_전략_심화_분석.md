# 데이터 저장 전략 심화 분석

## 🔍 질문에 대한 답변

### Q1: 로컬 저장은 항상 인터넷 연결이 필요한가?

**답변: 아니요. 로컬 저장은 인터넷 연결이 필요 없습니다.**

#### 로컬 저장 (SQLite)의 특징
- ✅ **오프라인 작동 가능**: 인터넷 연결 없이도 작동
- ✅ **로컬 파일 시스템**: EC2 서버의 디스크에 직접 저장
- ✅ **실시간 저장**: 네트워크 지연 없이 즉시 저장
- ❌ **단일 서버 제한**: EC2 서버가 다운되면 데이터 접근 불가
- ❌ **백업 필요**: 수동 백업 또는 자동 백업 설정 필요

#### 인터넷 연결이 필요한 경우
1. **실시간 모니터링 대시보드 접근** (웹 브라우저)
2. **알림 전송** (이메일, SMS, 푸시)
3. **원격 데이터 조회** (다른 서버에서 접근)
4. **클라우드 백업** (S3 등으로 자동 백업)

#### 오프라인 작동 시나리오
```
센서 → ESP32 → 로컬 서버 (EC2) → SQLite 저장
         ↓
    (인터넷 연결 불필요)
         ↓
    데이터는 로컬에 저장됨
         ↓
    인터넷 연결 복구 시
         ↓
    대시보드에서 조회 가능
```

### Q2: 샘플링 간격 조정이 용량에 영향을 주는가?

**답변: 네, 샘플링 간격 조정은 용량에 직접적인 영향을 줍니다.**

#### 현재 시스템 (60초 간격)
- **1분당**: 1개 샘플 (5초 오디오)
- **1일**: 1,440개 샘플
- **데이터 크기**: 0.46 GB/일

#### 샘플링 간격별 비교

| 간격 | 1분당 샘플 | 1일 샘플 수 | 일일 용량 | 월간 용량 | 절감률 |
|------|-----------|-----------|----------|----------|--------|
| 60초 | 1개 | 1,440개 | 0.46 GB | 13.8 GB | 기준 |
| 5분 | 0.2개 | 288개 | 0.09 GB | 2.76 GB | 80% ↓ |
| 10분 | 0.1개 | 144개 | 0.05 GB | 1.38 GB | 90% ↓ |
| 30분 | 0.03개 | 48개 | 0.015 GB | 0.46 GB | 97% ↓ |
| 1시간 | 0.017개 | 24개 | 0.008 GB | 0.23 GB | 98% ↓ |

**핵심**: 샘플링 간격을 늘리면 → 수집 횟수 감소 → 용량 감소

## 💾 데이터 저장 전략 비교

### 전략 1: 전체 오디오 파일 저장 (비권장)

**방식**: 모든 오디오 파일을 그대로 저장

**장점**:
- ✅ 원본 데이터 보존
- ✅ 나중에 재분석 가능

**단점**:
- ❌ 용량이 매우 큼 (5.52 GB/일)
- ❌ 대부분 정상 데이터 (불필요)
- ❌ 검색 및 분석이 느림

**비용**: $86.72/월 (전체 녹음 시)

---

### 전략 2: 스마트 저장 (현재 시스템, 권장)

**방식**: AI 분석 결과만 저장, 정상 데이터는 제외

**저장 조건**:
```python
# 정상이 아닌 경우만 저장
if analysis_result.get('is_overload', False):  # 이상 감지
    return True

if confidence < 0.8:  # 신뢰도 낮음 (주의)
    return True

if quality_metrics.get('score', 1.0) < 0.7:  # 품질 낮음
    return True
```

**저장 내용**:
- ✅ AI 분석 결과 (JSON)
- ✅ 특징 데이터 (압축된 MFCC 등)
- ✅ 메타데이터 (타임스탬프, 신뢰도 등)
- ❌ 오디오 파일 원본 (저장하지 않음)

**장점**:
- ✅ 용량이 매우 작음 (144 KB/일)
- ✅ 검색 및 분석이 빠름
- ✅ 비용 절감 (99% 이상)

**단점**:
- ❌ 원본 오디오 파일은 저장되지 않음
- ❌ 나중에 재분석 불가능

**비용**: $1.10/월 (프리티어 사용 시)

---

### 전략 3: 하이브리드 저장 (균형잡힌 접근)

**방식**: 이상 감지 시에만 오디오 파일 + 분석 결과 저장

**저장 조건**:
```python
# 이상 감지 시에만
if is_anomaly:
    # 1. 오디오 파일 저장 (압축)
    save_audio_file(audio_data, compressed=True)  # MP3
    
    # 2. AI 분석 결과 저장
    save_analysis_result(result)
    
    # 3. 특징 데이터 저장
    save_features(features)
```

**저장 내용**:
- ✅ 이상 감지 시 오디오 파일 (MP3 압축)
- ✅ AI 분석 결과
- ✅ 특징 데이터
- ❌ 정상 데이터는 저장하지 않음

**장점**:
- ✅ 이상 데이터는 원본 보존
- ✅ 용량이 적당함 (이상 발생률에 따라)
- ✅ 나중에 재분석 가능

**단점**:
- ❌ 이상 발생률에 따라 용량 변동

**비용**: 이상 발생률 5% 가정 시 약 $2-5/월

---

### 전략 4: 샘플링 + 스마트 저장 (최적화)

**방식**: 샘플링 간격 조정 + 스마트 저장 조합

**예시**:
- 샘플링 간격: 5분 (288 샘플/일)
- 저장 조건: 이상 감지 시에만
- 이상 발생률: 5% 가정

**계산**:
```
일일 샘플: 288개
이상 샘플: 288 × 0.05 = 14.4개
저장 용량: 14.4 × 160 KB = 2.3 MB/일
월간 용량: 2.3 MB × 30 = 69 MB/월
```

**비용**: $0.01/월 (거의 무료)

## 💡 저장 전략 최적화 아이디어

### 1. 적응형 샘플링
```python
# 정상 상태: 10분 간격
# 주의 상태: 5분 간격
# 이상 상태: 1분 간격
if normal:
    interval = 600  # 10분
elif warning:
    interval = 300  # 5분
else:  # anomaly
    interval = 60   # 1분
```

**효과**: 정상일 때는 용량 절감, 이상일 때는 상세 데이터 수집

---

### 2. 특징 데이터만 저장 (최소 용량)
```python
# 오디오 파일 대신 특징 데이터만 저장
features = extract_features(audio_data)  # 135개 특징
compressed_features = compress(features)  # 압축

# 저장: 약 1-2 KB/샘플
save_features(compressed_features)
```

**효과**: 오디오 파일 대비 99% 이상 용량 절감

---

### 3. 통계 요약 저장
```python
# 정상 데이터는 통계만 저장
if normal:
    # 하루 1회 통계 요약
    summary = {
        'date': '2024-01-15',
        'total_samples': 1440,
        'avg_confidence': 0.95,
        'avg_quality': 0.92
    }
    save_summary(summary)  # 1 KB/일
```

**효과**: 정상 데이터는 거의 용량 없이 추적 가능

---

### 4. 차등 압축
```python
# 정상: 높은 압축 (용량 절감)
# 이상: 낮은 압축 (품질 유지)
if normal:
    compression = 'high'  # MP3 64kbps
else:
    compression = 'medium'  # MP3 128kbps
```

**효과**: 정상 데이터는 더 압축, 이상 데이터는 품질 유지

## 📝 구현 권장사항

### 1. 저장 조건 명확화
```python
def should_store(audio_data, analysis_result):
    """저장 여부 판단"""
    # 이상 감지
    if analysis_result['is_anomaly']:
        return True, 'anomaly'
    
    # 신뢰도 낮음
    if analysis_result['confidence'] < 0.8:
        return True, 'low_confidence'
    
    # 품질 낮음
    if analysis_result['quality'] < 0.7:
        return True, 'low_quality'
    
    # 정상: 저장하지 않음
    return False, 'normal'
```
