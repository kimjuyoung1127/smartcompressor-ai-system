# 스마트 판단 아키텍처

## 개요

실시간 판단 시스템으로 대부분 자동 판단하고, 신뢰도가 낮은 데이터는 보류 큐에 추가하여 대시보드에서 수동 라벨링할 수 있는 모듈화된 아키텍처입니다.

---

## 아키텍처 흐름

```
[ESP32 오디오] 
    ↓
[실시간 판단 시스템]
    ↓
[신뢰도 판단]
    ├─ 신뢰도 높음 (≥ 0.7) → ✅ 자동 판단 완료
    └─ 신뢰도 낮음 (< 0.7) → 📋 보류 큐 추가
                              ↓
                          [대시보드]
                              ↓
                          [전문가 라벨링]
                              ↓
                          [라벨링 완료]
                              ↓
                          [재학습 데이터로 활용]
```

---

## 모듈 구성

### 1. SmartDetectionOrchestrator
**위치**: `services/smart_detection_orchestrator.py`

**역할**: 전체 워크플로우 오케스트레이션
- 실시간 판단 + 보류 라벨링 통합 관리
- 자동 판단 vs 보류 판단
- 대시보드 데이터 제공

### 2. RealtimeFailureDetectionService
**위치**: `services/realtime_failure_detection_service.py`

**역할**: 실시간 고장 판단
- MIMII 모델 (92% 정확도) 우선 사용
- 폴백 시스템 (80-90% 정확도)

### 3. PendingLabelingService
**위치**: `services/pending_labeling_service.py`

**역할**: 보류 라벨링 관리
- 보류 항목 저장 및 관리
- 라벨링 상태 추적
- 재학습용 데이터 제공

## 워크플로우

### 1단계: 실시간 판단

```python
from services.smart_detection_orchestrator import SmartDetectionOrchestrator

orchestrator = SmartDetectionOrchestrator(
    confidence_threshold=0.7,  # 신뢰도 임계값
    use_mimii_model=True
)

result = orchestrator.process_audio(
    audio_data=audio_array,
    device_id="ESP32_001"
)
```

### 2단계: 자동 판단 vs 보류

```python
if result['decision'] == 'auto':
    # ✅ 자동 판단 완료
    print(f"자동 판단: {result['result']['is_failure']}")
else:
    # 📋 보류 큐 추가
    print(f"보류 항목 ID: {result['pending_item_id']}")
```

### 3단계: 대시보드에서 보류 항목 조회

```python
# 보류 항목 목록
pending_items = orchestrator.get_pending_items_for_dashboard()

for item in pending_items['items']:
    print(f"ID: {item['id']}")
    print(f"신뢰도: {item['confidence']:.2%}")
    print(f"예측: {item['predicted_class']}")
```

### 4단계: 전문가 라벨링

```python
# 라벨링 완료
orchestrator.complete_labeling(
    item_id="pending_000001_1234567890",
    label="abnormal_overload",
    labeled_by="expert_001",
    expert_confidence=0.95
)
```

## API 엔드포인트

### POST /api/smart/detect
스마트 판단 (자동 판단 or 보류)

**Request:**
```json
{
  "audio_data": [0.1, 0.2, ...],
  "device_id": "ESP32_001",
  "sample_rate": 16000
}
```

**Response (자동 판단):**
```json
{
  "success": true,
  "decision": "auto",
  "result": {
    "is_failure": false,
    "confidence": 0.92,
    "method": "mimii"
  },
  "message": "자동 판단 완료: 정상"
}
```

**Response (보류):**
```json
{
  "success": true,
  "decision": "pending",
  "result": {
    "is_failure": false,
    "confidence": 0.55
  },
  "pending_item_id": "pending_000001_1234567890",
  "message": "신뢰도가 낮아 보류 큐에 추가되었습니다."
}
```

### GET /api/pending/items
보류 항목 목록 조회 (대시보드용)

**Query Parameters:**
- `device_id`: 디바이스 ID 필터 (선택적)
- `limit`: 최대 개수 (기본값: 50)

**Response:**
```json
{
  "success": true,
  "items": [
    {
      "id": "pending_000001_1234567890",
      "device_id": "ESP32_001",
      "timestamp": "2024-01-01T12:00:00",
      "confidence": 0.55,
      "predicted_class": "unknown",
      "audio_path": "data/pending_labeling/pending_000001_1234567890.wav"
    }
  ],
  "statistics": {
    "total": 100,
    "pending": 10,
    "completed": 85,
    "rejected": 5
  },
  "total_pending": 10
}
```

### POST /api/pending/items/<item_id>/label
보류 항목 라벨링

**Request:**
```json
{
  "label": "abnormal_overload",
  "labeled_by": "expert_001",
  "expert_confidence": 0.95,
  "notes": "과부하 징후 명확함"
}
```

**Response:**
```json
{
  "success": true,
  "item_id": "pending_000001_1234567890",
  "label": "abnormal_overload",
  "message": "라벨링이 완료되었습니다."
}
```

### GET /api/pending/items/<item_id>/audio
보류 항목의 오디오 파일 다운로드

## 대시보드 통합

### 대시보드 컴포넌트 예시

```javascript
// 보류 항목 목록 조회
async function getPendingItems() {
  const response = await fetch('/api/pending/items?limit=50');
  const data = await response.json();
  return data.items;
}

// 라벨링 완료
async function completeLabeling(itemId, label, expertId) {
  const response = await fetch(`/api/pending/items/${itemId}/label`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      label: label,
      labeled_by: expertId,
      expert_confidence: 0.95
    })
  });
  return response.json();
}
```

## 신뢰도 임계값 설정

### 기본값
- `confidence_threshold = 0.7` (70%)

### 조정 방법

```python
# 더 엄격하게 (더 많은 데이터 보류)
orchestrator = SmartDetectionOrchestrator(confidence_threshold=0.8)

# 더 관대하게 (더 적은 데이터 보류)
orchestrator = SmartDetectionOrchestrator(confidence_threshold=0.6)
```

### 보류 조건
1. 신뢰도 < 임계값
2. 점수가 중간값 (0.3 ~ 0.7)

## 데이터 흐름

### 자동 판단 경로
```
ESP32 → 실시간 판단 → 신뢰도 높음 → 즉시 결과 반환
```

### 보류 경로
```
ESP32 → 실시간 판단 → 신뢰도 낮음 → 보류 큐 저장
                                              ↓
                                      대시보드 표시
                                              ↓
                                      전문가 라벨링
                                              ↓
                                      재학습 데이터
```

---

## 재학습 연동

라벨링 완료된 항목은 재학습에 활용 가능:

```python
# 라벨링 완료 항목 조회
labeled_items = orchestrator.pending_service.get_labeled_items_for_training(limit=1000)

# 재학습 데이터로 변환
training_data = []
for item in labeled_items:
    training_data.append({
        'audio_path': item['audio_path'],
        'label': item['label'],
        'expert_confidence': item['expert_confidence']
    })
```

## 장점

1. **자동화**: 대부분의 데이터는 자동 판단 (약 90% 이상)
2. **품질 보장**: 불확실한 데이터만 전문가 검토
3. **점진적 개선**: 라벨링된 데이터로 모델 재학습 가능
4. **모듈화**: 각 컴포넌트가 독립적으로 작동
5. **확장성**: 대시보드와 쉽게 통합 가능
