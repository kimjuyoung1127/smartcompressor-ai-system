# 모듈화 아키텍처 설명

## 🎯 개선 목적

**연산 능력 절약**: 필요한 모듈만 사용하여 불필요한 연산 방지

---

## 📦 모듈 구조

### 1. DecibelFilter (데시벨 필터 모듈)

**역할**: 데시벨 기반 1차 필터링만 담당

**입력**: 데시벨 레벨

**출력**: 필터링 결과
- `skip`: 소리 없음 → 저장하지 않음
- `update_statistics_only`: 정상 (낮은 소리) → 통계만
- `needs_analysis`: 분석 필요

**연산 비용**: 매우 낮음 (단순 비교)

**사용 시점**: 항상 먼저 실행 (빠른 필터링)

---

### 2. FeatureExtractor (특징 추출 모듈)

**역할**: 오디오 특징 추출만 담당

**입력**: 오디오 데이터

**출력**: 특징 딕셔너리
- RMS 에너지
- 스펙트럼 중심
- 주파수 대역별 에너지 비율
- Zero Crossing Rate
- 패턴 안정성

**연산 비용**: 중간 (FFT, 특징 계산)

**사용 시점**: 데시벨 필터 통과 후 (48dB 이상)

---

### 3. SpectralAnomalyScorer (스펙트럼 이상 점수 계산 모듈)

**역할**: 이상 점수 계산만 담당

**입력**: 특징, 기준선

**출력**: 이상 점수 결과
- 종합 이상 점수 (0-1)
- 신뢰도
- 개별 특징별 이상 점수

**연산 비용**: 낮음 (Z-score 계산)

**사용 시점**: 특징 추출 후

---

### 4. FailureTypeClassifier (고장 유형 분류 모듈)

**역할**: 고장 유형 분류만 담당

**입력**: 특징, 이상 점수 결과

**출력**: 고장 유형 문자열
- 베어링 마모
- 파열음
- 냉매 누출
- 증발기 성에
- 언밸런스
- 마찰음

**연산 비용**: 매우 낮음 (조건문)

**사용 시점**: 이상 점수 계산 후

---

### 5. BaselineManager (기준선 관리 모듈)

**역할**: 기준선 설정, 저장, 로드만 담당

**입력**: 오디오 샘플 리스트

**출력**: 기준선 딕셔너리

**연산 비용**: 중간 (통계 계산, 초기 1회)

**사용 시점**: 초기 설정 시, 필요 시 로드

---

## 🔄 데이터 흐름 (모듈화)

```
ESP32 센서
    ↓
오디오 데이터 + 데시벨 레벨
    ↓
[DecibelFilter] 데시벨 기반 1차 필터링
    ├─ 35-40dB: skip → 종료 (연산 절약 ✅)
    ├─ 40-48dB: update_statistics_only → 종료 (연산 절약 ✅)
    └─ 48dB 이상: needs_analysis → 다음 단계
        ↓
[FeatureExtractor] 특징 추출 (필요한 경우만)
    ↓
[SpectralAnomalyScorer] 이상 점수 계산 (필요한 경우만)
    ↓
[FailureTypeClassifier] 고장 유형 분류 (필요한 경우만)
    ↓
결과 반환
```

## 💡 연산 능력 절약 효과

### 기존 방식 (단일 클래스)

**문제점**:
- 모든 단계를 항상 실행
- 불필요한 연산 발생

**예시**:
- 소리 없음 (35dB) → 특징 추출 + 이상 점수 계산 (불필요)
- 정상 (45dB) → 특징 추출 + 이상 점수 계산 (불필요)

---

### 모듈화 방식

**장점**:
- 필요한 모듈만 실행
- 불필요한 연산 방지

**예시**:
- 소리 없음 (35dB) → DecibelFilter만 실행 → 종료 (연산 절약 ✅)
- 정상 (45dB) → DecibelFilter만 실행 → 통계만 업데이트 (연산 절약 ✅)
- 분석 필요 (50dB) → 모든 모듈 실행

## 🎯 모듈별 독립성

### 장점

1. **독립 테스트 가능**
   - 각 모듈을 독립적으로 테스트
   - 모듈별 단위 테스트 작성 가능

2. **유지보수 용이**
   - 모듈별로 수정 가능

   - 다른 시스템에서 모듈 재사용 가능
   - 모듈별 라이브러리화 가능

---

### 모듈별 개별 사용

```python
from services.anomaly_detection_modules import (
    DecibelFilter,
    FeatureExtractor,
    SpectralAnomalyScorer
)

# 데시벨 필터만 사용
decibel_filter = DecibelFilter()
filter_result = decibel_filter.filter(decibel_level=35.0)

if filter_result['action'] == 'needs_analysis':
    # 특징 추출만 사용
    feature_extractor = FeatureExtractor()
    features = feature_extractor.extract(audio_data)
    
    # 이상 점수 계산만 사용
    scorer = SpectralAnomalyScorer()
    score_result = scorer.calculate(features, baseline)
```

### 연산 시간 절약

**일일 처리량** (센서 2개, 5분 간격):
- 총 샘플: 576개/일
- 소리 없음: 50% (288개) → 연산 절약 99%
- 정상 (낮은 소리): 30% (173개) → 연산 절약 99%
- 분석 필요: 20% (115개) → 정상 처리

**일일 연산 시간 절약**:
- 기존: 576 × 0.2초 = 115.2초
- 모듈화: 288 × 0.001초 + 173 × 0.001초 + 115 × 0.2초 = 23.3초
- **절약: 91.9초/일 (80% 절약)** ✅
