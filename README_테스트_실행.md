# ESP32 실시간 모니터링 테스트 실행 가이드

## 테스트 방법

### 방법 1: 시각적 데모 (권장)

**WSL 터미널에서 실행:**

```bash
cd /root/smartcompressor-ai-system
source venv/bin/activate
python scripts/test_esp32_visual_demo.py
```

**특징:**
- 단계별로 진행하며 Enter를 눌러 다음 단계로 이동
- 각 시나리오의 결과를 명확히 확인 가능
- 실제 작동하는 것을 시각적으로 보여줌

---

### 방법 2: 자동 테스트

**WSL 터미널에서 실행:**

```bash
cd /root/smartcompressor-ai-system
source venv/bin/activate

# 직접 서비스 테스트 (서버 불필요)
python scripts/test_esp32_realtime_system.py

# API 테스트 (서버 실행 필요)
python scripts/test_esp32_realtime_system.py --api
```

---

## 테스트 시나리오

### 시나리오 1: 소리 입력 없음 (35~40 dB)
- **입력**: 37.5 dB
- **예상 결과**: 🔇 소리 입력 없음
- **설명**: 알고리즘 실행 안 함

### 시나리오 2: 판단 임계값 미달 (40~48 dB)
- **입력**: 45.0 dB
- **예상 결과**: ⏸️ 판단 임계값 미달
- **설명**: 알고리즘 실행 안 함

### 시나리오 3: 정상 소리 (48 dB 이상, 높은 신뢰도)
- **입력**: 55.0 dB, 정상 소리
- **예상 결과**: ✅ 자동 판단 (정상)
- **설명**: 알고리즘 실행 → 자동 판단 완료

### 시나리오 4: 이상 소리 (48 dB 이상, 높은 신뢰도)
- **입력**: 60.0 dB, 이상 소리
- **예상 결과**: ✅ 자동 판단 (고장)
- **설명**: 알고리즘 실행 → 고장 감지

### 시나리오 5: 낮은 신뢰도 (48 dB 이상, 낮은 신뢰도)
- **입력**: 50.0 dB, 노이즈가 많은 소리
- **예상 결과**: 📋 보류 큐 추가
- **설명**: 알고리즘 실행 → 보류 큐에 추가 (대시보드에서 라벨링 필요)

## 문제 해결

### 문제: ModuleNotFoundError
**해결:**
```bash
source venv/bin/activate
pip install requests  # API 테스트 시 필요
```

### 문제: API 서버 연결 실패
**해결:**
- 서버가 실행 중인지 확인
- `python app.py` 실행 후 `--api` 옵션 사용
